Pendahuluan

Dokumen ini menyajikan pembaruan formal terhadap progress backend Chatbot Deka berdasarkan implementasi yang dapat diverifikasi langsung dari kode sumber project. Penyusunan laporan difokuskan pada kondisi backend terkini, sehingga isi dokumen tidak hanya menggambarkan rencana pengembangan, tetapi mencatat modul yang telah tersedia, alur yang telah berjalan, serta area yang masih berada pada tahap penguatan.

Secara umum, backend telah berkembang dari fondasi aplikasi Laravel dengan autentikasi sesi menuju sistem chatbot yang memiliki penyimpanan percakapan, integrasi runtime AI, alur streaming, knowledge retrieval berbasis RAG, pengelolaan feedback pengguna, dashboard analitik admin, serta modul role yang dikelola melalui tabel khusus. Dengan capaian tersebut, backend sudah berada pada tahap operasional inti dan tidak lagi hanya berupa fondasi awal.

Ringkasan Status Akhir

  • Autentikasi pengguna telah mendukung register, login, logout, pemeriksaan sesi, verifikasi email, reset password, dan Google OAuth.
  • Alur chat telah mendukung pembuatan percakapan, penyimpanan message, balasan JSON, serta Server-Sent Events; provider yang tidak mendukung stream native, termasuk Gemini, memakai respons final non-stream dalam kontrak SSE yang sama.
  • Runtime AI telah mencakup pembuatan jawaban, moderasi konten, pembuatan judul percakapan, perencanaan intent knowledge, penulisan query knowledge, perbaikan jawaban dari feedback dislike, dan konfigurasi model Gemini.
  • Guardrail output memblokir marker internal dan pola kebocoran instruksi prompt sebelum jawaban dikirim ke pengguna.
  • Knowledge base telah memiliki skema dokumen, chunk, ingestion run, proses ingest file dan crawl website, serta retrieval dengan mode pgvector maupun fulltext.
  • Fitur feedback sudah tersimpan per pesan assistant dan telah terhubung ke alur review admin, keputusan solve atau ignore, serta rekomendasi improvement berbasis AI.
  • Backend admin telah mencakup dashboard ringkasan, statistik token, tren chat, grafik feedback, daftar pengguna, daftar role, dan log aktivitas admin.
  • Modul role telah dipisahkan ke tabel roles, dilengkapi CRUD role admin, validasi assignment role pada pengguna, dan proteksi untuk role bawaan.

Arsitektur Backend Saat Ini

Arsitektur backend saat ini sudah tersusun dalam lapisan route, controller, service, runtime AI, dan persistence database. Request dari frontend masuk melalui route web dan API, kemudian controller meneruskan proses inti ke service yang memegang validasi bisnis, pemanggilan runtime AI, retrieval knowledge, dan pencatatan metadata. Di sisi admin, backend tidak hanya menampilkan data agregat, tetapi juga menyediakan endpoint tindakan untuk review feedback, CRUD user, CRUD role, dan laporan aktivitas.

Persistence Database menyimpan pengguna, role, percakapan, pesan, feedback, log aktivitas, dokumen knowledge, chunk knowledge, dan riwayat ingestion.

Progress Per Domain Backend

1. Auth, Keamanan, dan Identitas

Backend autentikasi telah memakai session-based authentication yang dipadukan dengan Fortify, verifikasi email, pembaruan password, penghapusan akun, dan autentikasi dua faktor. Endpoint auth API telah dipisahkan untuk kebutuhan frontend modern, sehingga alur login dan register dapat dipanggil secara asinkron tanpa meninggalkan pola sesi Laravel. Selain itu, login juga telah mendukung Google OAuth dan normalisasi email kanonik untuk menjaga konsistensi identitas pengguna.

2. Percakapan, Message, dan Streaming

Backend conversation telah mendukung pembuatan percakapan kosong maupun percakapan dengan pesan pertama, penyimpanan sequence message, pembangkitan judul percakapan, serta kepemilikan data berdasarkan user yang sedang login. Untuk kebutuhan pengalaman real-time, endpoint stream telah mengirim event SSE sampai jawaban final selesai lalu menyimpannya kembali ke database beserta metadata pemakaian model.

3. Runtime AI

Runtime AI dipusatkan pada AiRuntimeClient yang menangani reply chat, streaming, moderasi, pembuatan judul, perencanaan intent knowledge, penulisan query knowledge, reranking kandidat knowledge, dan pembuatan usulan improvement dari feedback dislike. Konfigurasi contoh kini menyediakan model Gemini. Saat provider Gemini dipakai, request ke endpoint stream diselesaikan sebagai respons final non-stream agar kontrak SSE tetap konsisten tanpa bergantung pada stream native provider. Pola ini menunjukkan backend sudah memakai pemisahan tanggung jawab yang cukup baik, karena controller tidak berhubungan langsung dengan detail provider AI.

4. Knowledge Base dan RAG

Knowledge backend telah mengalami perluasan dari pendekatan sederhana menjadi modul RAG yang lebih umum. Ingestion dapat berasal dari file lokal dengan format txt, md, html, pdf, dan docx, serta dari crawl website. Konten dibersihkan, dipecah menjadi chunk, diberi metadata, lalu disiapkan untuk retrieval menggunakan similarity vector ataupun pencarian full-text PostgreSQL. Jika context tidak memadai, backend telah menyiapkan fallback agar jawaban tidak keluar dari cakupan informasi Deka.

5. Feedback, Review, dan Audit

Backend telah memiliki mekanisme bagi pengguna untuk memberi like atau dislike pada pesan assistant. Khusus dislike, data alasan pengguna dapat ditindaklanjuti admin melalui status review, keputusan selesai atau diabaikan, catatan admin, serta saran perbaikan jawaban yang dihasilkan AI. Di sisi yang sama, aktivitas admin juga sudah dicatat pada tabel audit untuk mendukung kebutuhan pelacakan tindakan penting.

6. Pengguna, Role, dan Dashboard Admin

Area admin saat ini tidak hanya berisi visualisasi frontend, melainkan juga didukung backend yang menyiapkan data agregat, daftar pengguna, daftar role, serta endpoint tindakan. Modul role backend sudah dipisahkan ke tabel roles dengan fields deskriptif, data permissions, dan pembatasan penghapusan untuk role sistem. Assignment role pada pengguna telah tervalidasi terhadap data role yang tersedia, sehingga konsistensi data antar tabel menjadi lebih terjaga.
